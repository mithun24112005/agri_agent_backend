# Authentication & API Gateway Architecture

## Overview
A new Express.js API gateway sits in front of the existing FastAPI LangGraph backend to handle user authentication, authorization, and rate limiting using Redis.

## Layer Responsibilities

| Component        | Responsibility                  |
| ---------------- | ------------------------------- |
| Express          | Authentication + API gateway    |
| SQLite auth DB   | Users + authentication metadata (Sessions, Refresh Tokens) |
| Redis            | Rate limiting ONLY              |
| FastAPI          | AI backend                      |
| LangGraph SQLite | Conversation persistence        |
| Qdrant           | Vector retrieval                |
| Streamlit        | Temporary frontend              |

## Security Implementations
- **Refresh Token Rotation**: Refresh tokens are cryptographically hashed in the SQLite database. When used, the old token is revoked and a new one is issued transactionally.
- **Strict Identity Validation**: The gateway relies strictly on the validated JWT for user identity (`req.user.id`).
- **Server-Side Session IDs**: Sessions are mapped to users and generated by the server using `uuid`.
- **FastAPI Protection**: The `/chat` endpoint on FastAPI now requires an `X-Internal-API-Key` header verified against `INTERNAL_API_SECRET` to prevent direct public access.
- **Redis Rate Limiting**: IP-based limits for Auth endpoints (login/register). User+IP-based limits for expensive AI Chat endpoints, with robust fail-safes (503 Service Unavailable if Redis is down).

## Future Migration
The authentication database is designed using Prisma ORM with SQLite currently configured. In the future, modifying the `DATABASE_URL` in the `.env` file and running `npx prisma db pull/push` will seamlessly allow migrating to **PostgreSQL** without changing application code.
